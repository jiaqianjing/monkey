# Monkey 0.2.3 · 恢复中文输入与候选

日期：2026-10-30（Asia/Shanghai）。版本 0.2.3，build 5，Apple Silicon（arm64），最低要求 macOS 13.0。

## 对应问题与修复

0.2.2 发布后，用户反馈选中 Monkey 仍只有英文、没有中文候选及设置面板。0.2.3 修正了输入服务连接命名、输入客户端获取和设置请求转发；本机安装后，用户已通过实体键盘确认中文候选及“你好”上屏恢复。

- 连接名改为 `org.monkey.inputmethod.Monkey_Connection`，服务与 Info.plist 读取同一配置。
- 输入回调优先使用系统传入的客户端，再回退到控制器客户端，避免暂时缺少客户端时丢弃事件。
- 单实例判断与设置窗口请求限定同一应用路径，减少开发副本与安装版本之间的干扰。
- 增加不含输入正文、字符、按键码或客户端内容的路由诊断。

上述是已识别兼容风险的修正；现有证据不能单独归结为唯一根因。修复与构建源码提交为 `884212aa3efb7b8aeaee1d9da3fbf7fffb2c138d`。

## 下载与安装

[下载 0.2.3 公证 ZIP](https://github.com/jiaqianjing/monkey/releases/download/v0.2.3/Monkey-0.2.3-macos-arm64-notarized.zip)，解压后双击 **Monkey Installer.app**，点击 **安装**，再从菜单栏选择 **Monkey 拼音**。

输入法与安装器继续使用 Developer ID 正式签名、Apple 公证及附加票据，不通过关闭 Gatekeeper 或删除隔离属性修复输入。macOS 仍可能显示正常的首次下载打开确认。更新保留词库、学习数据、偏好与账号连接。

## 实际验证

- 本机 `swift test`：49 项通过。
- 用户在已打开的「文本编辑」文稿中亲手输入 `nihao` 并按空格，确认候选出现并输入“你好”。
- 用户随后返回原来输入失败的输入框，重复选择 Monkey、输入 `nihao` 并按空格，确认同样恢复。原输入框的宿主应用名称未记录，不据此声称全部应用均已验收。
- 当前 Mac 已安装 0.2.3（5）；设置窗口实际打开并显示正确版本。
- 两个应用的代码签名、票据、Gatekeeper、syspolicy 检查通过；最终 ZIP 解压后再次验证资源、内嵌 payload 与票据。

本轮未重新验证翻译流程，也没有另一台干净 Mac / VM 或所有支持系统的新增验收证据。旧版的翻译测试不能代替本版对应流程的实测。
